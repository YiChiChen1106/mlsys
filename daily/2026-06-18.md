### Concepts I Can Explain

- Why a local model directory plus `HF_HUB_OFFLINE=1` avoids network variance and container-side Hugging Face failures.
- Why TTFT, TPOT, latency, throughput, memory, and failure rate all matter together.
- Why concurrency increases throughput but can raise TTFT and latency.
- Why throughput under concurrency should use wall-clock time, not summed per-request latency.
- Why warmup requests should be outside the measured benchmark window.
- Why token throughput should use server-reported completion tokens.
- Why repeated prompts can activate prefix cache and hide prefill cost.
- Why request-id-only varied prompts can still leak prefix-cache state across prompt buckets, and why a per-run salt helps.
- Why `max_tokens` is only an upper bound; the model may stop earlier.
- Why admission uses `prompt_tokens + requested max_tokens <= max_model_len`.
- Why prefill TTFT and decode TPOT should be separated when judging TP=1 vs TP=2.
- Why tensor parallel speedup is limited by cross-GPU communication.
- Why visible GPU memory does not simply halve under tensor parallelism.
- Why p95/p99 latency matters for scheduler optimization.
- Why tail TTFT can reveal queueing or batch-admission behavior that average TTFT hides.

### Confusions / Mistakes

- The first concurrent benchmark counted warmup time in measured wall time, which underestimated throughput.
- The first token count used whitespace estimation, which was not rigorous enough for token throughput.
- `nvidia-smi --format=csv,noheader,nounits` worked, but one earlier command variant produced `Format modifier is not recognized`.
- `scp` does not resume a partially transferred file cleanly, so the half-transferred shard was deleted and resent.
- Medium and long prompts in the current prompt set are not truly long enough to stress prefill; synthetic longer prompts are needed next.
- Dual 4090 topology is `SYS`, so TP=2 communicates over PCIe/CPU interconnect rather than NVLink.
- TP=2 still improved this short-output benchmark, but the speedup stayed below 2x because communication and serving overhead remain.
- TP2 improved p99 latency and p99 TTFT at concurrency 16, not just average throughput.
- My first synthetic prefill rerun did not use `--vary-prompts`, so it was cache-sensitive and should not be used as the clean prefill conclusion.
- My second synthetic prefill rerun used request-id variation but no per-bucket salt, so cross-experiment prefix-cache reuse was still possible.
