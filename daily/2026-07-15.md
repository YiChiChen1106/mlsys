## Review: NCCL Collectives And PyTorch Distributed

Topic:

- NCCL collectives,
- PyTorch `torch.distributed`,
- all-reduce,
- all-gather,
- reduce-scatter,
- all-to-all,
- P2P send/recv.

Core mental model:

```text
torch.distributed = API that framework code calls
NCCL = GPU communication backend
PCIe/NVLink/RDMA = physical communication paths
```

Collective vs P2P:

```text
collective:
all ranks in the process group participate

P2P:
one rank sends to another rank
```

Inference mapping:

```text
Tensor Parallel:
all-reduce / all-gather / reduce-scatter

Pipeline Parallel:
P2P send/recv

Expert Parallel:
all-to-all

Prefill-Decode Disaggregation:
P2P / RDMA / KV-transfer layer
```

Connection to `pink`:

```text
GPU0 <-> GPU1 topology was SYS, not NVLink.
TP=2 improved throughput, but communication overhead limited scaling.
```

Chinese interview sentence:

```text
在 PyTorch 里我通常通过 torch.distributed 调通信原语，NVIDIA GPU 上常用 NCCL backend。collective 是所有 rank 一起参与的通信，比如 all-reduce、all-gather、reduce-scatter 和 all-to-all；P2P 则是 send/recv 这种点对点通信。LLM 推理里，TP 常见 all-reduce、all-gather、reduce-scatter，PP 常见 P2P activation transfer，EP/MoE 常见 all-to-all token dispatch，PD disaggregation 则会涉及 KV cache transfer。通信开销取决于 tensor 大小、频率、overlap 和底层拓扑，比如 PCIe/SYS、NVLink/NVSwitch 或 RDMA/GPUDirect RDMA。我的双 4090 机器没有 NVLink，所以 TP=2 虽然提高吞吐，但不会线性加速到 2x。
```
