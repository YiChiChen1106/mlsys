## Beginner Review: RadixAttention Deeper

RadixAttention is SGLang's automatic prefix KV cache reuse mechanism.

Core flow:

```text
new request tokens
-> longest prefix match in radix tree
-> reuse matched prefix KV cache
-> prefill only unmatched suffix
-> insert new suffix KV cache back into the tree
```

Example:

```text
cached:
system prompt + tool instruction + summarize

new request:
system prompt + tool instruction + summarize document B
```

Matched prefix:

```text
system prompt + tool instruction + summarize
```

Only this suffix needs new prefill:

```text
document B
```

## Node Split Intuition

If an existing cached sequence and a new sequence overlap partially:

```text
existing: A B C D
new:      A B X Y
```

The tree can split at the shared prefix:

```text
A B
├── C D
└── X Y
```

This avoids storing both full prompts independently.

## Eviction And Safety

Prefix cache cannot grow forever because GPU memory is limited.

Useful beginner rules:

- Evict old, inactive cache entries first.
- Do not evict KV cache still used by running requests.
- Reference counts help protect running batches.
- LRU-style leaf eviction is a natural policy.

## Scheduler Connection

RadixAttention can influence scheduling.

If one waiting request can reuse a long cached prefix and another cannot, a cache-aware scheduler may prefer the request with a larger cache hit because it requires less prefill work.

This connects:

```text
prefix cache hit rate
-> lower prefill work
-> lower TTFT
-> better throughput
-> scheduler/cache-system co-design
```

## Beginner Review: Structured Outputs And Constrained Decoding

Structured output means the model must generate text that satisfies a formal constraint:

- JSON schema,
- regular expression,
- EBNF grammar,
- tool-call schema.

The problem:

```text
free-form generation may produce invalid JSON
invalid JSON can break parsers, tool calls, and downstream systems
```

Constrained decoding fixes this at decode time:

```text
normal decoding:
sample from many likely next tokens

constrained decoding:
only allow tokens that keep the output valid
```

SGLang structured output docs say a request can specify one of:

- `json_schema`,
- `regex`,
- `ebnf`.

SGLang also supports grammar backends such as XGrammar, Outlines, and Llguidance.

## Compressed FSM Intuition

The SGLang paper discusses compressed finite state machines for faster constrained decoding.

Beginner mental model:

```text
if the schema already determines some syntax tokens,
the engine should not waste full model sampling work on every deterministic token
```

For JSON, many parts can be schema-driven:

```text
{ } [ ] : , "field_name"
```

Compressed FSM can compress deterministic multi-token paths and focus model generation on parts that need semantic content.


## Beginner Review: Speculative Decoding

Speculative decoding is a decode acceleration technique.

Core flow:

```text
draft model/module proposes several future tokens
target model verifies them in parallel
accepted draft tokens are committed
rejected tokens fall back to target-model generation
```

The goal is to reduce expensive target-model decode steps.

Key metric:

```text
acceptance rate
```

Higher acceptance means one target verification step can commit more tokens.

## EAGLE And MTP

EAGLE:

```text
uses a lightweight draft module based on target-model features
to produce better speculative tokens
```

EAGLE-2:

```text
uses context-aware dynamic draft trees
because acceptance rate depends on context
```

EAGLE-3:

```text
improves drafting with direct token prediction and multi-layer feature fusion
```

MTP:

```text
Multi-Token Prediction
model predicts multiple future tokens, not only the next token
```

MTP can be used as a speculation source during inference.

## Practical Tradeoff

Speculative decoding helps when:

- draft tokens are cheap,
- acceptance rate is high,
- output length is non-trivial,
- target verification can accept multiple tokens per step.

It may help less or hurt when:

- concurrency is already high,
- GPU is saturated,
- draft overhead is large,
- acceptance rate is low,
- extra memory reduces serving capacity.

## Chinese Interview Sentence

```text
Speculative decoding 的核心是 draft-then-verify。一个更便宜的 drafter 先猜多个未来 token，然后大模型 target 在一次并行 forward 里验证这些 token。如果 draft tokens 被接受，就相当于一次 target forward 生成了多个 token，从而降低 decode latency。关键指标是 acceptance rate：接受率越高，每次昂贵 target verification 能提交的 token 越多，收益越大。

```
