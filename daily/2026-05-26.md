## Concepts I Can Explain

- `memory bandwidth bound`: runtime is dominated by moving data, not doing arithmetic.
- `partial sum`: each Triton program reduces one chunk of the input into one local sum.
- `BLOCK_SIZE` sweep: measure several block sizes because larger blocks reduce partial sums but may reduce parallelism.
- `two-stage reduction`: first reduce `x[N]` into partial sums, then reduce partial sums into one scalar.
- `PyTorch baseline vs Triton kernel`: `torch.sum` is already highly optimized; Triton helps build intuition and may improve small overheads.

## Confusions / Mistakes

- A Triton program is not exactly one CPU-style thread. It processes a vector of offsets and maps to GPU execution.
- `reduction` means many values are combined into fewer values, often one scalar.
- `x + 1` is not a reduction because it is elementwise: one input element maps to one output element.
