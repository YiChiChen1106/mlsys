## Beginner Review: vLLM vs SGLang

Both vLLM and SGLang are high-performance LLM serving frameworks.

Shared concepts:

- OpenAI-compatible serving,
- continuous batching,
- KV cache management,
- prefix caching,
- multi-GPU parallelism,
- chunked prefill,
- optimized inference runtime.

Beginner distinction:

```text
vLLM:
general-purpose high-throughput LLM serving engine

SGLang:
serving/runtime framework with stronger emphasis on structured generation,
programmatic LLM workflows, and prefix-heavy workloads
```

## PagedAttention vs RadixAttention

PagedAttention:

```text
main question:
How do I store many variable-length KV caches efficiently?
```

It manages KV cache using block/page-style memory management.

RadixAttention:

```text
main question:
How do I reuse KV cache across requests with shared prefixes?
```

It organizes reusable prefix KV cache with a radix-tree-style structure.

Short version:

```text
PagedAttention = efficient KV storage
RadixAttention = efficient prefix reuse
```

## Chinese Interview Sentence

```text
我会把 vLLM 和 SGLang 都看成高性能 LLM serving framework，但侧重点不完全一样。vLLM 更像通用高吞吐 serving engine，核心亮点是 PagedAttention、continuous batching、OpenAI-compatible API、tensor parallel、prefix cache 和 metrics，所以我先用它搭了 benchmark lab，系统测 TTFT、TPOT、吞吐、KV pressure 和 scheduler 参数。

SGLang 也支持高性能 serving，但它更强调结构化生成、程序化 LLM workflow 和 prefix-heavy 场景。它的 RadixAttention 会把可复用的 KV cache 前缀组织到 radix tree 里，方便跨请求和复杂 workflow 复用共享前缀。简单说，vLLM 的 PagedAttention 更偏 KV cache 存储管理，SGLang 的 RadixAttention 更偏共享前缀复用。下一步我会在同一台双 4090 机器上跑 SGLang，用同样 workload 对比 prefix cache、TTFT、TPOT 和 scheduler 行为。
```
