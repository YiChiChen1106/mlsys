## Beginner Review: P95 And P99

P95 and P99 are latency percentiles.

If all request latencies are sorted from fastest to slowest:

- P95 means 95% of requests are no slower than this value.
- P99 means 99% of requests are no slower than this value.

They measure tail latency.

Why this matters:

- Average latency can hide a small number of very slow requests.
- Scheduler pressure, KV cache pressure, and queueing often appear first in P95/P99.
- In serving systems, user experience is often affected by tail latency, not only average latency.

Chinese interview sentence:

```text
P95/P99 是延迟百分位数，用来看尾延迟。P95 表示 95% 的请求延迟不超过这个值，P99 表示 99% 的请求延迟不超过这个值。相比平均延迟，P95/P99 更容易暴露高并发下少数慢请求的问题，比如排队、KV cache 压力和 scheduler 竞争。
```

## Beginner Review: Context Length And max_model_len

`max_model_len` is the maximum total sequence length allowed for one request.

For generation:

```text
total sequence budget = prompt_tokens + requested max_tokens
```

The server checks requested `max_tokens`, not actual generated tokens, because generation has not happened yet.

Experiment example:

```text
max_model_len = 2048
prompt_tokens = 1968
```

Accepted case:

```text
1968 + 80 = 2048
```

Rejected case:

```text
1968 + 81 = 2049
```

Why this matters:

- A prompt can fit by itself but still be rejected if requested output is too large.
- The server must reserve capacity based on the maximum requested sequence budget.
- This is connected to KV cache because each accepted token position may need cache capacity.

Chinese interview sentence:

```text
max_model_len 限制的是单个请求的总序列长度，不是只看 prompt 长度。对于生成请求，服务端要检查 prompt_tokens + requested max_tokens 是否小于等于 max_model_len。这里用 requested max_tokens，而不是实际生成 token 数，因为生成前服务端不知道模型会不会提前停止。我的实验里 max_model_len=2048，1968-token prompt 请求 80 个 output token 正好通过，1968+81=2049 就被 vLLM 拒绝。
```
